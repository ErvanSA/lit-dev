# Audit Aksesibilitas — wec-ui

Tinjauan aksesibilitas menyeluruh (Fase 2). Metode: tinjauan pola ARIA/keyboard
per komponen + unit test interaksi (Vitest + happy-dom). Verifikasi visual
(screen reader nyata / kontras otomatis) direncanakan lanjut bersama tim QA.

## Pola yang dipakai semua komponen

1. **Styling state via atribut reflect** (`[disabled]`, `[invalid]`, `[variant]`)
   sehingga selector CSS dan ARIA selalu sinkron dengan state.
2. **Fokus ring token**: `outline: 2px solid var(--wec-color-border-focus)`
   pada `:focus-visible`; varian invalid memakai warna `--wec-color-semantic-danger`.
3. **Wiring ARIA terpusat**: `wec-form-field` menghubungkan id label/hint/error
   ke kontrol (`labelledBy`/`describedBy` untuk komponen `wec-*`, atribut
   `aria-*` untuk kontrol native).
4. **Kontras**: pasangan warna teks/latar selalu dari token semantik berpasangan
   (`brand-primary` ↔ `brand-on-primary`, `semantic-danger` ↔ `semantic-on-danger`,
   dst.) — tema light dan dark keduanya tersedia.

## Temuan & tindakan (Fase 2)

| Temuan                                             | Tindakan                                                                                            | Status              |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------- |
| Switch butuh semantik switch, bukan checkbox biasa | `role="switch"` + `aria-checked` di input internal                                                  | ✅                  |
| Radio group perlu semantik grup + navigasi panah   | `role="radiogroup"`; radio native di-slot → navigasi panah native browser                           | ✅                  |
| Placeholder select bisa tak terbaca SR             | placeholder = `<option hidden>` native; saat `required` tidak `disabled` agar validasi native jalan | ✅                  |
| Icon dekoratif bisa kebisingan SR                  | default `aria-hidden="true"`; opsi `label` untuk `role="img"`                                       | ✅                  |
| Loading button masih fokusabel                     | `<button>` internal `disabled` saat `loading` (bukan sekadar `pointer-events`)                      | ✅                  |
| Card `interactive` tanpa akses keyboard            | tidak memaksa tabindex; dokumentasi mewajibkan kontrol fokusabel di dalam kartu yang bisa diklik    | ✅ (terdokumentasi) |

## Batasan & rencana lanjut

- Verifikasi dengan **screen reader nyata** (NVDA/VoiceOver) belum dilakukan —
  jadwalkan bersama QA.
- Verifikasi **kontras otomatis** (ax.dev / axe) dan **visual regression**
  menyusul bila pipeline browser test diaktifkan kembali.
- Komponen overlay berikutnya (`modal`, `tooltip`, `tabs`) wajib menyertakan:
  focus trap, `aria-modal`/`aria-expanded`, dan pengembalian fokus — pola
  sudah dicatat di sini sebagai prasyarat DoD.
